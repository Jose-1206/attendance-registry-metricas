# HU-08 — Generate a temporary QR code for a class session

## Story

**As** an authenticated teacher  
**I want** to generate a temporary QR code for one of my class sessions  
**so that** enrolled students can register attendance for the correct session during its validity period.

## Acceptance criteria

```gherkin
Scenario: Generate a temporary QR code
  Given I am authenticated with the TEACHER role
  And an existing class session belongs to one of my courses
  When I request a QR code for that session
  Then the system generates a unique token associated with that session
  And assigns an expiration time according to the agreed validity period
  And returns the information needed to display the QR code
  And the portal displays the QR code and its expiration time

Scenario: Reject generation for a nonexistent session
  Given I am authenticated with the TEACHER role
  When I request a QR code for a session that does not exist
  Then the system rejects the request
  And indicates that the session was not found
  And does not create a QR code

Scenario: Reject generation for another teacher's session
  Given I am authenticated with the TEACHER role
  And a class session belongs to another teacher's course
  When I request a QR code for that session
  Then the system rejects the operation
  And does not create or return a QR code

Scenario: Reject generation by a student
  Given I am authenticated with the STUDENT role
  When I attempt to generate a QR code for a class session
  Then the system rejects the operation because it requires the TEACHER role
  And does not create a QR code

Scenario: Reject generation without a valid JWT
  Given my JWT is missing, invalid, or expired
  When I request a QR code for a class session
  Then the system rejects the request as unauthenticated
  And does not create or return a QR code
```

This story does not enter sprint planning until it meets
[definition-of-ready.md](../../00-governance/definition-of-ready.md) in full.

- [ ] Confirm the QR generation operation, response fields, and QR payload format with the API contract.
- [ ] Confirm the validity period and the authoritative clock used to calculate expiration.
- [ ] Confirm teacher ownership checks and any session-status restrictions.
- [ ] Confirm whether generating another QR code invalidates previous codes for the same session.
