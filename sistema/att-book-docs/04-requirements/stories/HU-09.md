# HU-09 — Record attendance by scanning a QR code

## Story

**As** an authenticated student  
**I want** to scan a class session's QR code  
**so that** my attendance is recorded for that session.

## Acceptance criteria

```gherkin
Scenario: Record attendance with a valid QR code
  Given I am authenticated with the STUDENT role
  And I am enrolled in the course associated with the class session
  And the QR code belongs to that session and has not expired
  And I have no attendance record for that session
  When I scan and submit the QR code
  Then the system creates exactly one attendance record for my account and that session
  And records the check-in time when the valid scan is successfully processed
  And the portal confirms that my attendance was recorded

Scenario: Reject an expired QR code under BR-05
  Given I am authenticated with the STUDENT role
  And I am enrolled in the session's course
  And the QR code has reached or passed its expiration time
  When I submit the QR code
  Then the system rejects the check-in
  And indicates that the QR code has expired
  And does not create an attendance record

Scenario: Reject an invalid QR token
  Given I am authenticated with the STUDENT role
  When I submit a malformed or unknown QR token
  Then the system rejects the check-in
  And indicates that the QR code is invalid
  And does not create an attendance record

Scenario: Prevent a QR code from registering attendance for another session under BR-05
  Given I am authenticated with the STUDENT role
  And a valid QR code belongs to a specific class session
  When I submit that QR code
  Then the system resolves the session from the validated QR code
  And does not allow the request to associate attendance with a different session

Scenario: Reject a student who is not enrolled under BR-06
  Given I am authenticated with the STUDENT role
  And a valid QR code belongs to a course in which I am not enrolled
  When I submit the QR code
  Then the system rejects the check-in
  And indicates that enrollment in the course is required
  And does not create an attendance record

Scenario: Reject duplicate attendance under BR-07
  Given I am authenticated with the STUDENT role
  And I already have an attendance record for the class session
  When I submit a valid QR code for that session again
  Then the system rejects the duplicate check-in
  And indicates that my attendance is already registered
  And preserves the original attendance record and check-in time

Scenario: Prevent duplicates from concurrent submissions under BR-07
  Given I am authenticated with the STUDENT role
  And I am enrolled in the session's course
  And I have no attendance record for that session
  When two valid check-in requests for my account and that session are processed concurrently
  Then exactly one attendance record exists for my account and that session
  And the additional request does not create or overwrite an attendance record

Scenario: Reject attendance registration by a teacher
  Given I am authenticated with the TEACHER role
  When I attempt to register attendance through the student check-in operation
  Then the system rejects the operation because it requires the STUDENT role
  And does not create an attendance record

Scenario: Reject attendance registration without a valid JWT
  Given my JWT is missing, invalid, or expired
  When I submit a QR code
  Then the system rejects the request as unauthenticated
  And does not create an attendance record
```

## Affected module and requirements

|---|---|

## Definition of ready

This story does not enter sprint planning until it meets
[definition-of-ready.md](../../00-governance/definition-of-ready.md) in full.

- [ ] Confirm the check-in operation, QR payload, response fields, and rejection responses with the API contract.
- [ ] Confirm that the student identity comes from the authenticated account and the session comes from the validated QR code.
- [ ] Confirm the authoritative clock and time zone used for expiration and check-in timestamps.
- [ ] Confirm the persistence constraint and transaction behavior that prevent concurrent duplicate attendance.
- [ ] Confirm portal behavior when camera permission is denied or the QR code cannot be read.
